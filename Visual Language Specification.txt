Matheus Vieira Portfolio — Visual Language Specification
Document Purpose
This specification reverse-engineers the complete visual language of the Matheus Vieira product design portfolio. It is intended to serve as an implementation guide for AI agents, design tools, and engineering teams tasked with generating new screens, components, or marketing materials that must maintain perfect visual consistency with the existing product family.
The source interface is a single-page portfolio with case study overlays, built around an ultra-restrained, editorial, Swiss-inspired aesthetic. Every rule documented below has been extracted from the existing codebase and visual output. When multiple patterns exist, the canonical pattern is identified and documented. Novelty is strictly subordinated to consistency.
________________


1. Overall Design Philosophy
Design Principles
1. Restraint as Signal The interface communicates quality, taste, and confidence through what it refuses to do. Every element that could be added—shadows, gradients, multiple accent colors, decorative illustrations, heavy borders—is intentionally omitted. The resulting quietness forces the viewer to focus on content and typographic refinement. Restraint is not emptiness; it is a deliberate design decision that signals premium positioning.
2. Typography as Primary Hierarchy In this language, hierarchy is created almost exclusively through type scale, weight, and font family selection. Color plays a supporting role at best. Serif italic display type creates emotional peaks; sans-serif uppercase labels create structural rhythm; sans-serif body copy delivers information. If you find yourself reaching for color to differentiate importance, you have failed the system.
3. Whitespace as Structure Physical separators (borders, lines, boxes) are used minimally and at low opacity. Instead, whitespace carries the structural load. Sections are separated by massive vertical padding (80px to 256px). Content breathes. Grid gaps are generous. The absence of visual clutter is itself a structural system.
4. Warm Minimalism The aesthetic is not cold or clinical. The off-white background (#F5F2F0), warm near-black ink (#1A1A1A), and muted sage accent (#A5B8B1) create a human, tactile minimalism. It avoids the sterility of pure white (#FFFFFF) and pure black (#000000). Every neutral has a warm undertone.
5. Editorial Pacing The interface reads like a high-end editorial publication. Content is revealed progressively. Large hero moments alternate with dense information sections. Statistics are presented with typographic drama. Quotes are set in large italic serif. The pacing is intentionally uneven—some sections whisper, others declare.
Emotional Tone
* Calm and confident: No urgency, no alarms, no aggressive CTAs
* Intellectual and refined: Appeals to design-literate audiences
* Warmly austere: Minimal but not hostile; quiet but not empty
* Professionally vulnerable: The designer's voice comes through typography, not personality graphics
Product Positioning
This is a senior/junior product designer portfolio targeting tech companies and design teams in São Paulo. The positioning is: "I am a thoughtful, research-driven designer with taste." The interface must feel expensive to produce—not because of decoration, but because of precision.
Visual Restraint
The following are permanently forbidden by the design philosophy:
* Gradient backgrounds or gradient text
* Drop shadows on any element
* Border-radius above 4px on structural elements (0px preferred)
* Multiple accent colors competing for attention
* Decorative illustrations or geometric patterns
* Animation that feels playful, bouncy, or game-like
* Pure white (#FFFFFF) or pure black (#000000)
* Background colors other than the specified off-white and near-black
* Busy textures or noise overlays
* Underlines on body text links (except where explicitly designed)
* Colored backgrounds behind text blocks (the off-white is the only text background)
Interface Philosophy
"Less, but better." — Dieter Rams
The interface should feel inevitable. Every element should appear as if it could not be removed without breaking the communication. If an element can be removed and the message remains intact, it must be removed. This is not minimalism for aesthetic preference; it is minimalism as functional clarity.
Design Goals
1. Communicate taste and restraint
2. Showcase case study content without interface competition
3. Create a calm reading environment for dense design documentation
4. Maintain consistent visual language across homepage, case studies, and UI kit
5. Feel native to the web while referencing print editorial traditions
Premium Cues
Premium positioning is signaled through:
* Exceptionally generous whitespace (sections feel expensive because they "waste" space)
* Serif display typography (associations with editorial print)
* Single accent color used with extreme restraint
* Custom cubic-bezier easing curves on animations (not default browser easing)
* Careful attention to cursor states (crosshair default, pointer on interactive)
* Hardware-mimicking device frames with physical borders (8px stone border, not shadow)
What Should Never Happen Visually
* A button with a gradient background
* A card with a drop shadow
* A modal with a colored overlay (only blur + warm white opacity)
* Body text set in the serif font (serif is display-only)
* Multiple font families beyond Fraunces and Instrument Sans
* Bright, saturated colors (red, blue, orange, purple) in the interface
* Animated entrance effects that are fast, bouncy, or elastic
* Centered body text (center alignment reserved for hero and select moments only)
* All-caps body text (all-caps reserved for labels and metadata only)
* Colored text for emphasis (emphasis comes from size, weight, or italic, not color)

2. Visual Hierarchy
Typography Hierarchy
The hierarchy follows this strict cascade:
Level 1 — Hero Display
* Font: Fraunces, italic
* Size: 72px
* Weight: 300
* Line height: 1.0
* Usage: Homepage name, major section declarations, emotional peaks
* Always left-aligned or centered within its container; never justified
Level 2 — Section Headline
* Font: Fraunces, italic
* Size: 48px
* Weight: 300
* Line height: 1.1
* Usage: Case study titles, major section headers, quote blocks
* Can be wrapped in a "ghost marker" decorative treatment for section dividers
Level 3 — Sub-headline
* Font: Fraunces, italic
* Size: 36px
* Weight: 300
* Line height: 1.2
* Usage: Sub-section headers, feature callouts within case studies
Level 4 — Site Subtitle
* Font: Fraunces, italic
* Size: 15px
* Usage: Homepage role descriptor ("Designer de Produto")
Level 5 — Body Lead
* Font: Instrument Sans
* Size: 18px (implied by text-lg) or 20px (implied by text-xl)
* Weight: 400
* Line height: 1.6
* Usage: Case study narrative, descriptive paragraphs, research insights
Level 6 — Body
* Font: Instrument Sans
* Size: 13px
* Weight: 400
* Line height: 1.5
* Usage: Default body copy, descriptions, metadata
Level 7 — Label / Metadata
* Font: Instrument Sans
* Size: 10px
* Weight: 500
* Text transform: uppercase
* Letter spacing: 0.12em
* Usage: Navigation, captions, section labels, stat descriptors, tokens
Level 8 — Micro
* Font: Instrument Sans
* Size: 11px
* Weight: 500
* Text transform: uppercase
* Letter spacing: 0.08em
* Usage: Button text, component tokens, mini-labels
Whitespace Hierarchy
Whitespace increases with importance:
* Between major sections: 128px to 256px (py-32 to py-64, or custom py-24, py-40)
* Between content blocks within a section: 32px to 48px
* Between related elements: 16px to 24px
* Between label and content: 8px to 16px (mb-2, mb-4, mb-6, mb-8)
* Internal component padding: 20px to 24px (p-6 for cards, p-8 for sections)
* Line spacing in dense text: 1.5 to 1.6
Rule: When in doubt, double the whitespace. The interface errs on the side of too much breathing room rather than too little.
Contrast Hierarchy
* Maximum contrast: Near-black ink (#1A1A1A) on off-white (#F5F2F0) — used for primary reading text
* Medium contrast: 60% opacity ink on off-white — used for secondary descriptions
* Low contrast: 30% to 40% opacity ink — used for placeholder text, disabled states, captions
* Structural contrast: Stone (#E6E2DF) blocks on off-white — used for image placeholders, device frames
* Accent contrast: Sage (#A5B8B1) — used extremely sparingly for category labels, decorative emphasis, and subtle highlights
Critical Rule: Do not introduce new opacity values. The system uses 100%, 70%, 60%, 50%, 40%, 30%, 20%, and 10% opacity on the ink color. These are the canonical values.
Emphasis Rules
1. Primary emphasis: Large Fraunces italic + size contrast
2. Secondary emphasis: Uppercase label with generous letter-spacing
3. Tertiary emphasis: Opacity shift (100% → 60%)
4. Quaternary emphasis: Sage accent color on a small label or decorative element
5. Forbidden emphasis: Bold weight on body text, colored text for emphasis, underline for emphasis, background highlight boxes
Primary vs. Secondary Information
* Primary: The user's eye should land on the Fraunces italic headline first
* Secondary: The supporting description paragraph, set in Instrument Sans at comfortable line height
* Tertiary: Metadata labels (uppercase, 10px, letter-spaced)
* Quaternary: Placeholder captions, disabled states, decorative ghost markers
How Actions Compete
Actions do not compete. The interface avoids multiple competing CTAs. When two buttons exist side by side (e.g., Cancel and Confirm), they are visually quiet:
* Primary: filled ink background, off-white text
* Secondary: transparent background, ink border at 10% opacity
* Ghost: no background, no border, underline on hover only
Buttons never use color to differentiate. The hierarchy is: fill > outline > text-only.
Progressive Disclosure Principles
1. Homepage: Minimal information. Only name, role, one-line bio, and three navigation links.
2. Hover/Interaction: Navigation links and project links reveal on hover (underline scale, opacity shifts).
3. Panel Toggle: Clicking a nav item replaces the bio text with panel content (projects list, about, contact) in the same physical space.
4. Overlay: Clicking a project opens a full-screen overlay with the complete case study.
5. Scroll: Case studies reveal content through scrolling, with sticky sidebars maintaining context.
The rule: Never show everything at once. Reveal in stages based on user intent.

Page Gutters
* Desktop: 32px to 48px (px-8 to px-12, or custom 40px)
* Mobile: 30px (px-[30px] or px-8)
* Maximum content width: 1280px (max-w-7xl)
* Hero container: 420px max-width, centered
Section Spacing
Major sections are separated by massive whitespace. The canonical pattern is:
section {
  padding-top: 128px;
  padding-bottom: 128px;
}
Or in Tailwind: py-32. Some sections use py-24 (96px), py-40 (160px), or py-64 (256px) for dramatic pacing.
Rule: If a section contains a major visual element (hero image, device mockup), increase the surrounding whitespace by 50%.
Card Spacing
Cards use internal padding of 24px (p-6) to 32px (p-8). Card-to-card gaps are 24px to 32px (gap-6 to gap-8).
No card shadow. No card border-radius (0px). Cards are defined by 1px borders at 10% opacity or by stone-colored backgrounds.
Internal Component Spacing
* Button padding: 12px vertical, 24px horizontal
* Input padding: 12px vertical, 16px horizontal
* Label to input: 8px margin-bottom
* Icon to text: 8px to 12px gap
* Tag internal: 4px vertical, 10px horizontal
Density Philosophy
Low density. This is an editorial portfolio, not a dashboard. Information is presented one idea at a time. A section that could contain 6 data points might contain 3, with each given more whitespace. The interface should feel like turning pages in a coffee table book, not scanning a spreadsheet.
Breathing Room Rules
1. Every element must have at least 8px of clear space on all sides
2. Text blocks should never touch images or borders without at least 16px padding
3. Major sections must have at least 64px separation
4. When two sections have different background colors (e.g., off-white to near-black), the transition should be full-bleed with no gap
5. Content within a section should be centered within its max-width container, leaving generous side margins on large screens

4. Layout Principles
Page Width
* Full viewport width: Used for hero sections, full-bleed imagery, dark/light section transitions
* Constrained width: 1280px max-width (max-w-7xl) with auto margins, used for text-heavy content, case study body, grids
* Narrow width: 420px max-width, used exclusively for homepage hero content
Container Sizing
Three canonical containers:
1. Full-bleed: width: 100vw, no padding, used for color-block sections and hero images
2. Standard: max-width: 1280px, margin: 0 auto, padding: 0 32px, used for case study content
3. Narrow: max-width: 420px, centered, used for homepage text
Alignment Rules
* Left-alignment is canonical for all body content, section headers, and lists
* Center-alignment is reserved for: homepage hero, footer CTAs, centered statistics, and specific decorative moments
* Asymmetric offset: The case study layout consistently uses a 12-column grid where the label sits at col-start-1 col-span-3 and the content sits at col-start-5 col-span-7. This 2-column offset creates editorial tension and whitespace on the left.
* Right-alignment is never used for text
Responsive Behavior
* Desktop (primary): Full 12-column grid, asymmetric offsets, sticky sidebars, hover-reveal navigation
* Tablet: Maintains grid but reduces column spans; increased gutters
* Mobile:
   * Navigation becomes always-visible (no hover dependency)
   * Single-column layouts
   * Reduced section padding (80px instead of 128px)
   * Hero container gets padding: 0 30px
   * 12-column grid collapses to single column
Critical Mobile Rule: The hover-reveal navigation on the homepage becomes permanently visible on mobile. Hidden content must not rely exclusively on hover.
Stacking Rules
When stacking elements vertically:
1. Label/Metadata always sits above the content it describes
2. Images sit below their captions (caption above, image below — or image full-bleed with caption overlay/after)
3. Statistics sit in horizontal rows with equal spacing
4. Quotes sit indented with a left border (2px, sage-colored)
Visual Rhythm
The rhythm alternates between:
* Dense text sections: Asymmetric grid, left labels, right content
* Full-bleed visual sections: Large images, device mockups, hero photos
* Statistics rows: 4-column grids with large numbers
* Divider sections: Ghost marker text (large decorative section labels)
* Dark inversions: Near-black background with off-white text for contrast and reset
The pattern is: Text → Visual → Text → Statistics → Divider → Text → Visual → Dark → Text. This alternation prevents visual fatigue.
Reading Flow
1. Eye lands on the largest Fraunces italic element
2. Drops to the uppercase label above or beside it
3. Reads the supporting paragraph
4. Scans metadata/statistics
5. Moves to the next section via whitespace
The Z-pattern is broken intentionally; the reading flow is more of a slow waterfall with pauses.
Content Grouping
* Proximity grouping: Related elements sit close together (8px–16px)
* Separation grouping: Unrelated sections sit far apart (128px+)
* Border grouping: 1px borders at 10% opacity separate subsections within a page
* Background grouping: Stone-colored blocks (#E6E2DF) group visual content without borders

* Line height for long text: 1.6 (generous, prevents fatigue)
* Paragraph spacing: 1.5em between paragraphs, or explicit margin utilities

6. Color Language
Semantic Color Usage
Colors are not decorative. Each color has a specific semantic role:
Color
	Hex
	Role
	Off-white
	#F5F2F0
	Primary background, canvas, negative space
	Ink
	#1A1A1A
	Primary text, borders (at low opacity), filled buttons, dark sections
	Stone
	#E6E2DF
	Secondary surface, image placeholders, device frames, skeletons
	Sage
	#A5B8B1
	Accent — labels, decorative borders, category tags, emphasis
	Grayscale Philosophy
The interface lives in a warm grayscale, not a neutral or cold one.
* Background: Warm off-white with a hint of pink/beige (#F5F2F0)
* Text: Warm near-black with a hint of brown (#1A1A1A), not pure black
* Mid-tone: Warm gray (#E6E2DF) that matches the undertone of the background
This warmth prevents the interface from feeling clinical or corporate. It feels like paper, like a gallery wall, like natural stone.
Accent Colors
One accent color only: Sage (#A5B8B1).
Usage rules for the accent:
* Section category labels (e.g., "Case Study" tag above a title)
* Decorative left borders on blockquotes (2px)
* Category tags with filled background
* Subtle emphasis on ghost markers
* NEVER used for primary actions, buttons, or large backgrounds
The sage is desaturated and muted. It does not demand attention; it whispers.
Interactive Colors
* Default interactive: Ink (#1A1A1A) at 100% opacity
* Hover state: Opacity reduction to 60–70%, or underline reveal
* Active/pressed: Scale transform (0.98), slight opacity shift
* Disabled: Ink at 30% opacity, cursor: not-allowed
* Destructive action: Terracotta (#C4705A) — rare, reserved for delete confirmations only
* Success: Not explicitly colored; communicated through check icons and copy
* Error: Terracotta (#C4705A) for form validation messages
Background Strategy
Two canonical backgrounds:
1. Off-white (#F5F2F0): Used for 90%+ of the interface. This is the "page."
2. Ink (#1A1A1A): Used for inverted sections (cheat sheet, dark footers, result sections). Text switches to off-white.
Rule: No other background colors are permitted. Do not use stone (#E6E2DF) as a section background; it is reserved for content blocks, placeholders, and device frames within the off-white canvas.
Surface Hierarchy
1. Base layer: Off-white background
2. Content layer: Transparent (inherits off-white)
3. Frame layer: Stone (#E6E2DF) for image/device placeholders
4. Overlay layer: Off-white at 98% opacity with backdrop blur
5. Dark layer: Ink (#1A1A1A) for inverted sections
Border Colors
All borders use the same base color: rgba(26, 26, 26, 0.1) — ink at 10% opacity.
This creates an extremely subtle structural line that is visible only when looking for it. Borders separate without dividing.
Rule: If a border needs to be more visible, increase opacity to 30% or use a solid 1px line. Never use a different color for borders.
Emphasis Rules
When color SHOULD be used:
* To distinguish a filled tag (sage background for "Live" status)
* To communicate error state (terracotta)
* To create dark section inversion (ink background)
* For ghost marker text (sage, at very low opacity)
When color SHOULD NOT be used:
* For primary button backgrounds (use ink, not blue or sage)
* For link text (use ink with underline, not blue)
* For section backgrounds (use off-white or ink only)
* For emphasis within body text (use size/weight/italic, not color)
* For borders (use ink at 10%, not colored borders)
* For icon fills (icons are stroke-only, ink-colored)

8. Elevation System
Shadows
No drop shadows are used anywhere in the interface.
Shadows are forbidden by the flat, editorial aesthetic. Depth is not communicated through shadow; it is communicated through:
* Color contrast (off-white vs. stone vs. ink)
* Scale (hero elements are larger)
* Layering (overlays sit above content via z-index)
* Blur (backdrop-filter on overlays)
Surface Hierarchy
Surfaces exist on a flat plane but are separated by:
1. Z-index layering: Overlays (z-100) sit above body content
2. Backdrop blur: backdrop-filter: blur(4px) on overlay backgrounds creates a frosted glass effect that separates layers without shadows
3. Opacity: Overlay backgrounds use rgba(245, 242, 240, 0.98) — nearly opaque but slightly translucent
4. Color inversion: Dark sections (ink background) create strong separation from light sections
Floating Components
When a component needs to feel "above" other content:
1. Fixed navigation trigger: Bottom-left, z-[60], with bg-page-bg/80 backdrop-blur-md border border-10
2. Close button: Fixed top-right, z-110, transparent background
3. Modal overlay: Fixed, full-screen, z-100, semi-transparent off-white with backdrop blur
Rule: Floating components use backdrop blur and semi-transparent backgrounds, not shadows. They feel like frosted glass panels, not floating cards.
Layering

	Depth Philosophy
Flat depth. The interface rejects skeuomorphism and material design. Layers are separated by blur, opacity, and color, not by shadow casting. The aesthetic is two-dimensional with occasional frosted translucency.

9. Borders & Dividers
Border Strength
All borders are 1px solid. The strength varies by opacity:
* Structural sections: border-10 = rgba(26, 26, 26, 0.1) — the canonical border
* Subtle separators: border-ink/10 — same value
* Emphasis borders: border-sage — used for blockquote left borders and category tags
* Dark section borders: border-white/10 — off-white at 10% opacity on ink backgrounds
Divider Usage
Dividers are used sparingly. When content sections need separation:
1. Whitespace first: Prefer 128px padding over a divider line
2. Border second: Use border-t border-10 or border-y border-10 for subtle separation
3. Ghost marker third: Large decorative text ("Descoberta", "Síntese", "Design") acts as a section divider without a line
Separators
* Horizontal rules: border-t at 10% opacity ink
* Vertical rules: Used in blockquotes as 2px left border in sage
* Grid lines: Not used; whitespace separates grid items
Structural Lines
The interface uses invisible structure (whitespace, grid alignment) over visible lines. When lines appear, they are hairlines (1px) at low opacity.
Examples:
* border-t border-10 between stat sections
* border-y border-10 around a statistics row
* border-l-2 border-sage on blockquotes
* border border-10 on card containers
Invisible Structure
Most of the layout structure is invisible:
* 12-column grid guides placement but has no visible gutters
* Padding creates section boundaries without lines
* Asymmetric offsets (col-start-5) create alignment without visible columns
Rule: If you can see the structure without looking for it, it is too strong. Structure should be felt, not seen.

10. Iconography
Icon Family
The icon system is custom-drawn SVG line icons. No icon library (FontAwesome, Heroicons, etc.) is used directly; instead, simple geometric SVGs are embedded inline.
Style characteristics:
* Outline style (stroke only, no fill)
* Stroke width: 1.5px
* Size: 20×20px (canonical)
* Stroke linecap: round
* Stroke linejoin: round
* Color: Ink (#1A1A1A) or inherits current color

13. Motion Language
Animation Philosophy
Motion is slow, elegant, and purposeful. It references physical momentum rather than digital snap. The interface moves like heavy, well-balanced objects—sliding, fading, and blurring with weight.
Core principle: Animations should feel inevitable, not surprising. The user should anticipate the motion before seeing it.
Durations
Duration
	Usage
	0.3s
	Micro-interactions: hover underlines, border color shifts, opacity changes
	0.4s
	Navigation reveals, panel transitions
	0.5s
	Content panel fades, text opacity swaps
	0.8s
	Major transitions: overlay entry/exit, page-level transforms
	Easing
Easing
	Usage
	ease
	Default for simple opacity and color transitions
	cubic-bezier(0.16, 1, 0.3, 1)
	Canonical primary easing. Used for all major entrance animations. This is a smooth deceleration curve (fast start, slow finish). It feels luxurious and unhurried.
	cubic-bezier(0.76, 0, 0.24, 1)
	Custom smoother curve (implied by --transition)
	linear
	Skeleton shimmer animation
	Critical Rule: The cubic-bezier(0.16, 1, 0.3, 1) curve is the signature motion of this interface. It must be used for all overlay entrances, panel reveals, and filter transitions.
Transitions
Canonical transition property: transform and opacity and filter
Specific patterns:
* transition: transform var(--transition), filter var(--transition), opacity var(--transition) — for hero container when overlay opens
* transition: opacity 0.5s ease — for content panel toggles
* transition: opacity 0.4s ease, transform 0.4s ease — for navigation reveal
* transition: transform 0.3s ease — for underline scale
* transition: border-color 0.3s ease — for input focus
* transition: opacity 0.3s ease — for hover opacity shifts
Hover Animations
* Underline scale: transform: scaleX(0) → scaleX(1) on ::after pseudo-element
* Nav reveal: opacity: 0 + translateY(10px) → opacity: 1 + translateY(0)
* Opacity shifts: 100% → 60–70% on links
* Border darken: Ink at 10% → ink at 30% on cards
Modal / Overlay Transitions
Entry:
1. Overlay: opacity: 0 + translateY(20px) + pointer-events: none
2. To: opacity: 1 + translateY(0) + pointer-events: auto
3. Duration: 0.8s
4. Easing: cubic-bezier(0.16, 1, 0.3, 1)
5. Simultaneously: Body gets filter: blur(10px) + opacity: 0 + scale(0.98)
Exit:
* Reverse of entry
* Escape key triggers exit
Page Transitions
The single-page portfolio does not have page-to-page transitions. Instead:
* Homepage panels fade in/out
* Case study overlays slide up and blur the background
* Internal case study anchors scroll smoothly (implied by anchor links)
Micro-interactions
* Cursor: crosshair is the default cursor everywhere
* Interactive elements: cursor: pointer on links, buttons, and project links
* Close trigger: Opacity 50% → 100% on hover
* Ghost marker: Fixed large decorative text that sits behind content as a section indicator
What Kinds of Motion Should Never Be Used
1. Bouncy/spring physics: No elastic overshoot, no bounce effects
2. Fast snaps: No 0.1s or 0.15s transitions; everything is deliberate
3. Rotation: No spinning icons, no rotating loaders
4. Scale pop: No overscaled hover effects (buttons do not grow)
5. Color cycling: No animated gradients, no hue shifts
6. Parallax scrolling: No scroll-driven transform offsets
7. Staggered entrances: No cascade of elements entering with delays
8. Shake/error wobble: No physical shake on error
9. Page curl/flip: No 3D transforms
10. Typewriter effects: No character-by-character text reveal

14. Content Density
Dense vs. Relaxed Layouts
The interface is overwhelmingly relaxed.
Relaxed layout characteristics:
* Sections with 128px–256px vertical padding
* Single-column or asymmetric 2-column grids (not 4+ columns of text)
* Large font sizes with generous line heights
* One idea per section
Dense layout characteristics (used sparingly):
* Statistics rows with 4-column grids
* Component library grids (12-column icon grids)
* Case study metadata rows (4-column role/timeline/sector/impact)
Rule: When presenting narrative content (case studies, about text), use relaxed layouts. When presenting structured data (stats, component lists), use denser grids but maintain whitespace between items.
Information Prioritization
1. Most important: Large Fraunces italic headline
2. Second: Supporting paragraph (1–2 sentences)
3. Third: Metadata labels and statistics
4. Fourth: Decorative elements, placeholders, secondary actions
Scrolling Philosophy
Scrolling is natural and expected. The case study overlay is scrollable (overflow-y: auto). There is no "above the fold" anxiety—content is allowed to extend far below the viewport.
Scroll behaviors:
* No sticky headers (except the floating hamburger menu at bottom-left)
* Sticky sidebars used in case studies (sticky top-32) to maintain context while content scrolls
* No scroll-jacking or snap scrolling
* No progress indicators or scroll bars (custom scrollbar styling is minimal: 4px width, stone thumb)
Progressive Disclosure
The homepage is the most restrained view:
* Name + role + one-line bio
* Three nav links (Projetos, Sobre, Contato)
* Nav links reveal panel content on click
* Project list reveals case study on click
* Case study reveals full narrative on scroll
At each stage, information density increases:
* Homepage: Minimal
* Panel: Moderate (project list with brief descriptions)
* Overlay: Full (complete case study with all sections)
Hidden Actions
Actions are visually quiet by default:
* Navigation links are uppercase, small, and unadorned
* Project links are underlined text, not buttons
* The floating menu is hidden behind a hamburger icon at the bottom-left
* Close triggers are small, uppercase "Voltar" text at top-right
Rule: Do not show all available actions at once. Hide secondary actions behind hover, progressive disclosure, or compact icons.
Reveal Patterns
1. Hover reveal: Navigation fades in on homepage hover
2. Click reveal: Panels toggle on nav click; overlays open on project click
3. Scroll reveal: Case study content is naturally revealed by scrolling (no scroll-triggered animations in the canonical implementation, though ghost markers appear as section indicators)
4. Focus reveal: No explicit focus-triggered reveals

16. Accessibility
Contrast
* Primary text: Ink (#1A1A1A) on off-white (#F5F2F0) — ratio ~15:1 (exceeds AAA)
* Secondary text: Ink at 60% opacity on off-white — ratio ~4.5:1 (meets AA for large text, may need adjustment for small body text)
* Labels at 30% opacity: Not intended for reading; decorative/placeholder only
* Dark sections: Off-white on ink — ratio ~15:1 (exceeds AAA)
Rule: Ensure body text always uses 100% opacity ink or meets 4.5:1 contrast. 60% opacity is acceptable for descriptions above 13px; for smaller text, use higher opacity.
Touch Targets
* Buttons: Padding of 12px 24px creates adequate touch targets (minimum 44×44px)
* Navigation links: Padding of 10px 0 with adequate spacing
* Icon buttons: 20×20px icon within a larger clickable container
* Floating hamburger: Circular container with padding
Keyboard Navigation
* Escape key closes overlays and panels (implemented in JS)
* Tab order follows visual order
* Focus states should be added for production (currently minimal in the source)
Focus Visibility
The source code uses outline: none globally. For accessibility compliance:
* Add outline: 1px solid var(--ink); outline-offset: 2px for focused interactive elements
* Or use a subtle box-shadow focus ring that matches the flat aesthetic
Readability
* Line height: 1.5–1.6 for body text
* Line length: Capped by max-width containers and grid spans
* Font size: Minimum 10px for labels, 13px for body
Responsiveness
* Mobile breakpoints: 768px (max-width: 768px)
* Mobile adjustments: Always-visible nav, single-column grids, reduced padding (80px instead of 128px), 30px horizontal gutters
* No horizontal scroll
* Touch-friendly tap targets on mobile

17. Implicit Cohesion Rules
This is the most critical section. These are the hidden rules that make the interface feel like a single, intentional product.
1. Typography Carries Hierarchy; Color Does Not
The interface never uses color to indicate importance. A primary action and a secondary action are distinguished by fill vs. outline, not by blue vs. gray. If you find yourself wanting to use color to create hierarchy, use font size, weight, or family instead.
2. Whitespace Is Preferred Over Separators
When two sections need division, add 128px of padding before using a border. When items in a list need division, add 24px of gap before using a bullet or line. Structure is created by absence, not presence.
3. Interactive Elements Avoid Visual Noise
Buttons do not have shadows, gradients, or rounded corners. Links do not have background highlights on hover. The interface refuses to "sell" the action visually; it simply marks it as available and gets out of the way.
4. All Uppercase Text Must Have Increased Letter-Spacing
Uppercase labels without letter-spacing feel aggressive and cheap. The 0.12em tracking transforms uppercase text from shouting into whispering. This rule is non-negotiable.
5. Serif Is Emotional; Sans-Serif Is Functional
Fraunces italic is reserved for moments of human expression: names, headlines, quotes, decorative markers. Instrument Sans is reserved for functional communication: instructions, metadata, body copy, navigation. Never blur these roles.
6. Borders Are Invisible Until You Look for Them
All borders are 1px at 10% opacity. If a border is visible from across the room, it is too strong. Borders are for structure, not decoration.
7. The Single Accent Color Is a Spice, Not a Main Ingredient
Sage (#A5B8B1) appears in fewer than 5% of interface elements. It is used for category labels, quote borders, and occasional decorative text. It never appears in buttons, backgrounds, or large text blocks.
8. Animations Are Heavy and Slow
The 0.8s cubic-bezier(0.16, 1, 0.3, 1) transition feels like a heavy curtain rising or a gallery door sliding open. It is never snappy, never bouncy, never instant. Motion has mass.
9. Images Are Desaturated
Photography and imagery should have reduced saturation (approximately -10% from natural). The warm grayscale environment cannot support highly saturated images. Images should feel like they belong to the same world as the interface.
10. Pure Black and Pure White Are Forbidden
#000000 and #FFFFFF are too harsh for this warm, tactile minimalism. #1A1A1A (warm near-black) and #F5F2F0 (warm off-white) are the extremes.
11. Asymmetry Creates Editorial Tension
The 12-column grid consistently places labels at columns 1–3 and content at columns 5–7 (or 5–12). This left offset creates negative space that feels intentional, not broken. Centered layouts are the exception, not the rule.
12. The Crosshair Cursor Is a Statement
The default cursor is crosshair, not default arrow. This is a subtle signal that the interface is a design object, not a standard web document. Interactive elements switch to pointer. This must be preserved.
13. No Decorative Elements That Do Not Serve Information
There are no geometric shapes, no abstract illustrations, no decorative lines that do not carry meaning. Even the ghost markers ("Descoberta", "Síntese") serve as section indicators. If an element can be removed without losing information, it must be removed.
14. Device Frames Mimic Physical Hardware
Device mockups use 8px solid stone borders with 4px inner radius to simulate physical hardware. They do not use drop shadows to simulate depth; they use thick, flat borders to simulate mass.
15. Negative Space Is Content
A section with 256px of vertical padding and one line of text is not "empty"—it is paced. The whitespace is as much a design element as the text. Do not fill whitespace because you can.
16. Hover States Are Reveals, Not Transformations
On hover, elements reveal their true state (underline appears, opacity increases), rather than transforming into something new (no color changes, no background fills, no scale effects on hover).
17. Ghost Markers Provide Orientation Without Interference
Large, low-opacity decorative text ("Descoberta", "Síntese", "Design") sits behind or between sections to provide scroll orientation. They are not interactive, not selectable, and intentionally subtle (20% opacity or lower).
18. Feedback Is Inline and Structural
Error, success, and warning messages use left borders and outline icons, not floating toasts or modal alerts. They sit within the content flow, bordered and padded like other content blocks.
19. Statistics Are Presented as Typography
Numbers in statistics rows are set in large Fraunces (48–60px), not in chart graphics or data visualizations. The number itself is the visual.
20. Quotes Are Blocked and Bordered
Blockquotes use a left border (2px, sage) and large Fraunces italic. They are never wrapped in quotation mark characters; the typographic treatment replaces punctuation.
21. Loading States Respect the Aesthetic
Skeleton screens use the stone color with a subtle shimmer gradient. They do not use spinners, dots, or animated logos. The loading state is visually quiet.
22. Footer Is a Transition, Not a Termination
The footer does not contain columns of links, social icons, or legal text. It is a single CTA ("Próximo Projeto") set in large italic serif with an arrow. The portfolio never truly "ends"; it transitions.
23. One Type of Container Border
Cards, inputs, sections, and tags all use the same border treatment: 1px solid, ink at 10% opacity. There is no variety in border style. This unity is intentional.
24. Opacity Is a Core Design Tool
Opacity is not an afterthought for "disabled" states. It is used systematically to create hierarchy: 100% for primary, 60% for secondary, 40% for tertiary, 30% for disabled, 20% for placeholders, 10% for borders.
25. Case Studies Follow a Predictable Rhythm
Every case study section follows the pattern: Label → Headline → Paragraph → (Optional) Quote → Visual → Statistics. This rhythm creates consistency across projects.

18. Dos and Don'ts
30 DOs
1. DO use Fraunces italic at weight 300 for all display headlines and emotional text.
2. DO use Instrument Sans at weight 400 for all body text and weight 500 for all labels.
3. DO set all uppercase text with 0.12em letter-spacing minimum.
4. DO use #F5F2F0 as the default background for all pages and sections.
5. DO use #1A1A1A as the default text color (never pure black).
6. DO use #A5B8B1 as the only accent color, and use it sparingly.
7. DO use 1px borders at rgba(26, 26, 26, 0.1) for all structural separation.
8. DO use 0px border-radius for cards, buttons, inputs, images, and containers.
9. DO use generous whitespace: minimum 64px between sections, preferably 128px.
10. DO use the asymmetric 12-column grid offset (label at col-start-1, content at col-start-5).
11. DO use the cubic-bezier(0.16, 1, 0.3, 1) easing for all major transitions.
12. DO use 0.8s duration for overlay/page transitions and 0.3s for micro-interactions.
13. DO use scaleX underline reveals on hover for text links.
14. DO use opacity transitions (not color transitions) for hover states on links.
15. DO use cursor: crosshair as the default cursor and cursor: pointer on interactive elements.
16. DO use outline SVG icons with 1.5px stroke, no fill, 20×20px size.
17. DO use stone (#E6E2DF) for image placeholders, device frames, and skeleton backgrounds.
18. DO use left-aligned text as the default; center-align only for hero and select moments.
19. DO use sentence case for body text and all-caps for labels and metadata only.
20. DO use 1.6 line-height for body text and 1.0 for large display text.
21. DO use max-w-7xl (1280px) as the standard content container width.
22. DO use the hamburger menu pattern for floating navigation (bottom-left, backdrop blur).
23. DO use uppercase "Voltar" as the close trigger for overlays (not an X icon alone).
24. DO use blockquotes with a 2px sage left border and Fraunces italic text.
25. DO use statistics in large Fraunces numbers with uppercase 10px labels below.
26. DO use the panel-toggle pattern for homepage navigation (replace content in place).
27. DO use backdrop-filter blur (4px) on overlay backgrounds, not drop shadows.
28. DO use the ghost marker pattern for large section dividers (low-opacity decorative text).
29. DO ensure images are desaturated (~-10%) to match the warm grayscale environment.
30. DO use the primary/secondary/ghost button hierarchy with ink fill, outline, and text-only variants.
30 DON'Ts
1. DON'T use any font family other than Fraunces and Instrument Sans.
2. DON'T use Fraunces for body text, labels, buttons, or navigation.
3. DON'T use Instrument Sans for headlines, quotes, or display text.
4. DON'T use upright (non-italic) Fraunces for display text.
5. DON'T use any weight above 300 for Fraunces.
6. DON'T use pure black (#000000) or pure white (#FFFFFF) anywhere.
7. DON'T introduce new accent colors beyond sage (#A5B8B1).
8. DON'T use gradient backgrounds, gradient text, or gradient borders.
9. DON'T use drop shadows on any element, including cards, buttons, or modals.
10. DON'T use border-radius above 4px on any structural element (0px preferred).
11. DON'T use colored backgrounds for text sections (only off-white and ink are permitted).
12. DON'T use all-caps for body text, sentences, or paragraphs.
13. DON'T use uppercase text without increased letter-spacing (0.12em).
14. DON'T use underline for emphasis in body text.
15. DON'T use bold text (weight 700) anywhere in the interface.
16. DON'T use center alignment for body text, case study narratives, or lists.
17. DON'T use less than 64px vertical padding between major sections.
18. DON'T use decorative illustrations, geometric patterns, or abstract shapes.
19. DON'T use animated entrances that are bouncy, springy, or elastic.
20. DON'T use duration below 0.3s for any transition.
21. DON'T use default browser easing for major animations (always use the custom cubic-bezier).
22. DON'T use multiple competing CTAs in a single view.
23. DON'T use card shadows, lifted cards, or 3D perspective effects.
24. DON'T use background fills on input fields (transparent with border only).
25. DON'T use floating labels inside inputs (labels sit above).
26. DON'T use loading spinners, dots, or animated logos for skeleton states.
27. DON'T use toast notifications or snackbars (use inline feedback blocks).
28. DON'T use tab pills, rounded chips, or bubble-style tags.
29. DON'T use sidebar navigation with icons and backgrounds.
30. DON'T add elements "because they look nice"—every element must serve information hierarchy.

19. Implementation Checklist
Before generating any new UI, verify:
Typography
* Only Fraunces (italic, weight 300) and Instrument Sans (400, 500) are used
* Uppercase text has 0.12em+ letter-spacing
* Display text is tight (1.0–1.2 line-height); body text is relaxed (1.5–1.6)
* No bold (700) text exists
* No underline on body text (except explicit links with animated underline)
Color
* Background is #F5F2F0 (off-white) or #1A1A1A (ink) for dark sections only
* Text is #1A1A1A (never pure black)
* Only one accent: #A5B8B1 (sage), used sparingly
* No gradients, no shadows, no new colors
Spacing
* Sections have minimum 64px vertical padding, preferably 128px
* Content uses max-w-7xl (1280px) container with 32px side gutters
* Asymmetric grid offsets (col-start-1 vs col-start-5) for editorial layouts
* Whitespace separates sections, not heavy borders
Borders & Radius
* All borders are 1px at 10% ink opacity (rgba(26,26,26,0.1))
* All structural elements have 0px border-radius
* Only device hardware frames use 4px radius
Components
* Buttons are sharp (0px radius), uppercase, 11px, with hover underline or fill-swap
* Inputs are sharp, transparent, with 1px border
* Cards have no shadow, no radius, 1px border at 10% opacity
* Tags are sharp rectangles with 1px border
* No decorative elements that do not serve information hierarchy
Motion
* Major transitions use 0.8s cubic-bezier(0.16, 1, 0.3, 1)
* Micro-interactions use 0.3s ease
* No bouncy, springy, or fast animations
* Overlays use backdrop blur + opacity, not shadows
Accessibility
* Body text meets 4.5:1 contrast ratio
* Interactive elements have adequate touch targets (44×44px minimum)
* Focus states are visible (add minimal outline if not in source)
Cohesion
* Does this feel like the same product family?
* Is whitespace consistent with the generous editorial rhythm?
* Are hierarchy rules respected (typography > whitespace > opacity > color)?
* Is color used sparingly (sage accent < 5% of elements)?
* Are components following the same sharp, border-only, shadow-free proportions?
* Does the interface feel calm, unhurried, and confident?
* Is there any decoration that could be removed without losing meaning?
* Are all uppercase labels tracked at 0.12em?
* Are all borders at 10% opacity ink?
* Are all animations slow and smooth (never snappy)?
Final Sanity Check
* If you removed any single element, would the interface break or merely become cleaner?
* If the answer is "cleaner," remove it.
